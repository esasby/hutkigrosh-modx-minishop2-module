# Модуль оплаты ХуткiГрош (ЕРИП) для MODX Revolution + miniShop2

Модуль обеспечивает взаимодействие интернет-магазина на базе **MODX Revolution + miniShop2** с платёжным сервисом [ХуткiГрош](https://hutkigrosh.by): выставление счетов в ЕРИП (АИС "Расчет"), оплата картой (WebPay), QR-код, автоматическое обновление статусов заказов после оплаты.

## Поддерживаемые версии

Поддерживаются одновременно две версии модуля:

| | [HutkiGrosh API v3](#настройка-hutkigrosh-api-v3) (рекомендуется) | [HutkiGrosh](#настройка-hutkigrosh-предыдущее-поколение) (предыдущее поколение) |
|---|---|---|
| Текущая версия | 3.0.0 (`msphutkigrosh-3.0.0-pl.transport.zip`) | 2.0.0 (`msphutkigrosh-2.0.0-pl.transport.zip`) |
| API | актуальное поколение (REST API v3) | предыдущее поколение API |
| Подключение | API-токен, выбор услуги из списка | логин/пароль, ERIP ID вручную |
| Тестовая система | api-sandbox.hgrosh.by | trial.hgrosh.by |
| Кому подходит | новым магазинам и тем, кто переходит на API v3 | действующим магазинам, работает как раньше |

> Сервис ХуткiГрош сейчас поддерживает все поколения API параллельно.

Следите за анонсами о сроках отключения старого API и переходите на API v3 заранее (порядок перехода описан в разделе "[Одновременная работа и переход на API v3](#одновременная-работа-и-переход-на-api-v3)").

## Скачать

Для каждой версии модуля используется свой файл сборки (.transport.zip):

| MODX + miniShop2 | Сборка API v3 (рекомендуется) | Сборка предыдущего поколения |
|---|---|---|
| MODX Revolution 2.8.x + miniShop2 4.x | [msphutkigrosh-3.0.0-pl.transport.zip](https://github.com/esasby/hutkigrosh-modx-minishop2-module/blob/main/msphutkigrosh-3.0.0-pl.transport.zip) (проверено на 2.8.8 и 4.4.2) | [msphutkigrosh-2.0.0-pl.transport.zip](https://github.com/esasby/hutkigrosh-modx-minishop2-module/blob/main/msphutkigrosh-2.0.0-pl.transport.zip) (проверено на 2.8.8 и 4.4.2) |

Отдельная сборка API v3 обусловлена сменой поколения API сервиса, а не изменениями MODX: внутри одной версии CMS обе сборки отличаются только поколением API.

## Требования

- PHP 5.6 и выше, расширение [cURL](https://www.php.net/manual/ru/book.curl.php)

## Установка (одинакова для обеих версий модуля)

**MODX Revolution + miniShop2:**

1. Создайте резервную копию магазина и базы данных.
1. Скачайте архив нужной сборки (раздел "Скачать").
1. В административной части MODX выберите `Приложения > Установщик`, нажмите "Загрузить дополнения", затем "Загрузить пакет", укажите скачанный архив и установите его.
1. Перейдите в меню `Приложения > miniShop2 > Настройки > Способы оплаты`: добавьте новый способ оплаты с именем ХуткiГрош (Hutkigrosh) (если он уже существует, сделайте его активным) и назначьте ему способы доставки.
1. Создайте ресурс MODX для страницы успешного выставления счета:
   * Заголовок - `Успешная оплата`
   * Шаблон - Ваш стандартный шаблон
   * Содержимое - `[[!msHutkigroshSuccess]]`
1. Создайте ресурс MODX для страницы ошибки выставления счета:
   * Заголовок - `Неуспешная оплата`
   * Шаблон - Ваш стандартный шаблон
   * Содержимое - произвольный текст
1. Заполните параметры модуля (см. разделы настройки ниже).

## Настройка HutkiGrosh API v3

### Шаг 1. Получите API-токен

В бизнес-аккаунте ХуткiГрош откройте **Настройки > Интеграция ПУ** (раздел доступен ролям "Владелец ПУ" и "Администратор ПУ"). Используйте токен с доступом к информации о ПУ и созданию/редактированию счетов.

### Шаг 2. Подключите магазин

1. Откройте окно редактирования способа оплаты "ХуткiГрош" (`Приложения > miniShop2 > Настройки > Способы оплаты`): на вкладке "Настройки ХуткiГрош" вставьте токен в поле **API Token**.
1. Нажмите кнопку "Актуализировать", модуль загрузит из ХуткiГрош справочники для полей **Код услуги**, **Код торговой точки**, **Код кассы** (загруженные значения сохраняются в настройках и восстанавливаются при открытии формы без обращения к API).
1. Выберите значения в списках и сохраните изменения.

### Шаг 3. Остальные параметры

Остальные параметры настраиваются в `Системные настройки` MODX (область `ХуткiГрош`, фильтр по ключу `ms2_msphutkigrosh`):

**Основное:**
* **Название магазина**: произвольное название Вашего магазина.
* **Песочница**: тестовый режим работы, счета выставляются в тестовую систему `api-sandbox.hgrosh.by` с токеном тестовой системы.
* **Режим отладки**: запись в лог дополнительной отладочной информации.
* **Путь в дереве ЕРИП**: путь, по которому клиент будет искать выставленный счёт (например, `АИС "Расчет" (ЕРИП) > Интернет-магазины/сервисы >`).
* **Срок действия счёта (дней)**: как долго счёт будет доступен в ЕРИП для оплаты.

**Экран успешного заказа:**
* **Инструкция по оплате**: пошаговая инструкция по оплате счёта в ЕРИП.
* **QR-код**: оплата счёта по QR-коду через мобильное приложение банка (QR-код и ссылка на оплату запрашиваются у сервиса).
* **Оплата картой (Webpay)**: кнопка оплаты счёта картой (переход на Webpay).

**Статусы заказов** (выбор из существующих статусов магазина, список статусов - `Приложения > miniShop2 > Настройки > Статусы заказов`):
* **Статус при выставлении счёта**: какой статус установить заказу после выставления счёта в ЕРИП. Рекомендуется "Новый" (1), заказ ожидает оплаты.
* **Статус при оплате счёта**. Рекомендуется "Оплачен" (2), оплата получена, заказ ожидает комплектации и отправки.
* **Статус при отмене**. Рекомендуется "Отменён" (4).
* **Статус при ошибке**. Рекомендуется "Отменён" (4) либо созданный дополнительно статус для ошибок оплаты.

**Уведомления** (отправляются шлюзом ХуткiГрош):
* **Email оповещение**: письмо клиенту при успешном выставлении счёта.
* **SMS оповещение**: SMS клиенту при успешном выставлении счёта.

**Возврат клиента на сайт:**
* **Ресурс при успехе**: идентификатор ресурса, созданного при установке (см. "Установка"), на который клиент попадает после успешного выставления счёта.
* **Ресурс при ошибке**: идентификатор ресурса, созданного при установке (см. "Установка"), для перехода при ошибке выставления счёта.

### Обязательно: адрес обработчика уведомлений

Для автоматического обновления статуса заказа (после оплаты клиентом счёта в ЕРИП) сообщите в службу технической поддержки ХуткiГрош адрес обработчика, указав Ваш домен:

```
https://ваш-домен/assets/components/minishop2/payment/hutkigrosh.php?action=notify
```

Если MODX расположен в подпапке домена, адрес будет содержать соответствующий префикс (например, `https://ваш-домен/modx/assets/components/minishop2/payment/hutkigrosh.php?action=notify`).

Модуль принимает уведомление GET-запросом с идентификатором счёта (`purchaseid`) в URL.

### Тестовый режим (Sandbox)

1. Получите API-токен тестовой системы (выдаётся при регистрации в ХуткiГрош).
1. Включите в настройках модуля режим **Песочница** и настройте согласно инструкции выше.
1. Счета будут выставляться в тестовую систему `api-sandbox.hgrosh.by`.
1. Для эмуляции оплаты счёта используйте [личный кабинет](https://cabinet.hgrosh.by) (сверху-справа "Профиль пользователя" > "Тестовый режим").

Документация API v3: https://api-dev.hgrosh.by/eripservice/docs/ru/index.html

**Статусы заказов** (выбор из существующих статусов магазина, список статусов - `Приложения > miniShop2 > Настройки > Статусы заказов`):

## Одновременная работа и переход на API v3

* Обе сборки являются одним и тем же пакетом `msphutkigrosh` (общий способ оплаты и общие системные настройки): сборка API v3 устанавливается **поверх** предыдущей версии и замещает её файлы; заказы и данные магазина не затрагиваются. Обратный переход выполняется установкой предыдущей сборки поверх.
* Адрес обработчика уведомлений **не меняется**: сообщать в поддержку ХуткiГрош новый адрес не нужно.
* Способ оплаты в магазине остается прежним ("ХуткiГрош"): двойная обработка уведомлений исключена.
* Настройки со сходными ключами (статусы заказов, ресурсы, уведомления, "Название магазина", "Путь в дереве ЕРИП", "Срок действия счета") сохраняются при переходе; переключатели экрана успешного заказа нужно включить заново ("QR-код" и "Оплата картой (Webpay)" вместо "QR-код" и "Кнопка Webpay"); поля подключения меняются: вместо "Логин/Пароль/ERIP ID" заполняются "API Token" и справочники "Код услуги", "Код торговой точки", "Код кассы" (ранее сохраненные значения остаются в базе данных).

Рекомендуемый порядок перехода:

1. Создайте резервную копию магазина и базы данных.
1. Получите API-токен тестовой системы (см. "Настройка HutkiGrosh API v3", шаг 1).
1. Установите сборку API v3 поверх предыдущей версии (порядок установки см. в разделе "Установка").
1. На вкладке "Настройки ХуткiГрош" вставьте токен в поле "API Token", нажмите "Актуализировать" и выберите значения в списках "Код услуги", "Код торговой точки", "Код кассы".
1. Включите режим "Песочница" и проверьте выставление и оплату счёта (эмуляция оплаты в личном кабинете, см. "Тестовый режим").
1. Выключите "Песочницу" и вставьте токен, выданный для рабочей системы, в поле "API Token", нажмите "Актуализировать" и выберите значения в списках "Код услуги", "Код торговой точки", "Код кассы": счета будут выставляться в рабочую систему `api.hgrosh.by`.
1. Проверьте обработчик уведомлений: статус заказа в магазине должен измениться после оплаты счёта.
